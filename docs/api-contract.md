# Message Center API

All browser routes use the `mc_session` HttpOnly cookie; login is `POST /api/auth/login` with `{ "username": "DEV-AAA" }` (also DEV-BBB and DEV-CCC). `GET /api/auth/me` returns `{owner_id, name}` and `POST /api/auth/logout` ends the session. All demo identities can manage all data; authorization is deliberately permissive. `GET /api/config` reports integration configuration and `GET /api/people` returns the three owners. Lists are JSON arrays, mutations return the affected object, failures use FastAPI's `{detail: ...}`.

Message create `POST /api/messages`: `{title, body, kind?, source_id?, external_id?, client_request_key?, publisher?, topic?, channel?, metadata?: object (at most 8192 UTF-8 bytes as JSON), recipients?: [owner_id], expires_at?}`. Empty recipients use subscriptions matching channel/topic; nonempty recipients override subscriptions. Source ingestion uses exactly this message schema. `GET /api/messages` accepts `q`, `channel`, `topic`, `status`, `limit` (1–500, default 100), `offset`; `GET /api/messages/{id}` includes `revisions`, `deliveries`, `responses`, and `response_counts`. `PATCH /api/messages/{id}` accepts message content and targeting fields, creates a new version and cancels outstanding pending, accepted, and failed deliveries for older versions. `POST /api/messages/{id}/withdraw` withdraws it. `POST /api/messages/{id}/responses` takes `{owner_id?, response: "acknowledge"|"attending"|"declined", note?}`. `POST /api/messages/{id}/enrich` is optional and disabled unless explicitly configured.

Source `GET|POST /api/sources`, `PATCH /api/sources/{id}`, `DELETE /api/sources/{id}`: `{name, type: "webhook"|"poll"|"manual", enabled, url?, token?, poll_interval_seconds?}`. Tokens are write-only. For webhook `POST /api/ingress/{source_id}` supply `X-Source-Token` and the standard message object including external_id. A poll endpoint returns either one standard object or an array; external_id is required for both. Disabled sources reject ingress and are not polled.

Subscriptions `GET|POST /api/subscriptions`, `PATCH|DELETE /api/subscriptions/{id}`: `{owner_id, channel?, topic?, mode: "immediate"|"digest", enabled}`. Null channel/topic matches any. Each owner receives at most one delivery per version, immediate taking precedence if multiple subscriptions match. `GET /api/deliveries` optionally filters owner_id, status and message_id and supports limit and offset; `POST /api/deliveries/{id}/retry` requeues a failed receipt. `GET /api/dashboard` returns counts.

Service endpoints require `X-Message-Center-Token` matching `MESSAGE_CENTER_SERVICE_TOKEN`. `GET /api/integrations/duet/inbox?owner_id=...` lists that owner's delivery receipts with message. `GET /api/integrations/duet/messages/{id}?owner_id=...` returns detail. `POST /api/integrations/duet/messages` accepts the standard message object plus explicit owner_id and client_request_key. `POST /api/integrations/duet/messages/{id}/responses` accepts owner_id, response and note. `POST /api/integrations/duet/deliveries/{id}/result` accepts `{owner_id, status: "processed"|"failed", notified: bool, summary?}`. `notified=true` means an owner update was confirmed; false means no confirmation, not evidence that the owner has not seen it. Digest reporting cannot attribute an owner update to an individual receipt in this first version. Processing and notification do not imply human reading or feedback.

The worker sends `POST ${DUET_BASE_URL}/api/message-center/deliveries`, header `X-Message-Center-Token`, body `{delivery_id, message_id, version, owner_id, mode, message: {title, body, kind, source, publisher, topic, channel, created_at, expires_at}}`. Duet replies `{request_id, status: "accepted"}`; request_id can be null for digest receipts. Stable delivery_id makes retry idempotent. Digest deliveries use the same callback; Duet persists them without an immediate LLM wake and consumes them in system review. PostgreSQL is authoritative; Redis is only a wake hint.

Additional service routes: `GET /api/integrations/duet/messages?owner_id=...&q=...&channel=...&topic=...` searches active, unexpired messages; limit defaults to 20 and is capped at 100. With `summary=true`, each object has `body_excerpt` capped at 500 characters instead of `body`; use the detail route for full content. `GET /api/integrations/duet/subscriptions?owner_id=...`, `POST /api/integrations/duet/subscriptions` with the standard subscription object including owner_id, and `PATCH|DELETE /api/integrations/duet/subscriptions/{id}?owner_id=...` manage that owner's subscriptions. `POST /api/integrations/duet/deliveries/{id}/mark` with `{owner_id, consumed: bool}` marks Duet consumption; false restores accepted state. Browser-only `POST /api/deliveries/{id}/read` with `{owner_id, read: bool}` records an explicit human read/unread action in `human_read`; processing does not change it. Service subscription creation upserts a matching owner/channel/topic/mode and applies enabled state. Expired, withdrawn, or superseded deliveries reject results with HTTP 409; treat that response as terminal. Inbox and service search also accept limit and offset.
